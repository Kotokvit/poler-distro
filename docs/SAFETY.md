# POLER SAFETY — правила суверенной системы

Этот документ родился из реального инцидента: программа-ассистент (Gemini
Antigravity) разрешила удаление Bash при том, что установленная оболочка
являлась standalone-программой без проверенного фолбэка. Система работала
до первой перезагрузки, после чего доступ был потерят на ~3 часа. Ниже —
правила, которые делают такое невозможным в POLER CachyOS Sovereign Edition.

## Инцидент (пост-мортем, кратко)

1. На живой системе Bash был программно заменён на poler-sh 0.2.0 (standalone,
   из `Kotokvit/poler-sh` — НЕ терминал из `poler-engine-org/poler-engine`).
2. Вопрос «легаси (Bash) удалять можно?» получил ответ «да».
3. Bash был удалён. До перезагрузки всё работало: poler-sh уже был запущен в
   памяти, его интерпретатор не был нужен.
4. После перезагрузки: `sulogin`/`getty` не смогли запустить `/bin/sh` →
   emergency mode «root account locked» → консоль недоступна.
5. Параллельно сказался отказавший SATA-кабель (SCSI parity error) и
   повреждённая primary GPT — что усложнило диагностику.

**Корневая причина — не железо и не poler-sh. Корневая причина — удаление
единственного проверенного login-shell без фолбэка.**

## Железные правила

1. **Никогда не удаляйте единственный login-shell.** В `/etc/passwd` у root
   всегда должен быть рабочий shell, который вы ЛИЧНО запускали в этом сеансе.
   Меняете shell — сначала запустите новый, проверьте команды, `cd`, пайпы,
   редактор, и только потом трогайте старый (а лучше — вообще не удаляйте:
   место на диске дешевле трёх часов потери доступа).

2. **Прежде чем доверять ассистенту (ИИ) — требуйте проверяемый критерий.**
   Правильный ответ на «можно ли удалить Bash?» — «только после того как
   покажете: (а) новый shell запускается, (б) переживает перезагрузку,
   (в) содержит rescue-путь». Ответ «да, можно» без критериев — повод
   остановиться.

3. **Проверяйте перезагрузку немедленно.** Любое изменение загрузочной цепочки
   (shell, init, загрузчик, таблица разделов) проверяется контролируемой
   перезагрузкой СРАЗУ, пока у вас есть свежий live-USB и план отката.

4. **Terminal Gateway ≠ standalone poler-sh.** Терминал внутри
   `poler-engine-org/poler-engine` — это двойной контур исполнения с пайпами
   и редиректами. poler-sh 0.2.0 — это отдельная программа со своими
   ограничениями (нет `>`-редиректов). Это разные инструменты, и смешение
   их статусов привело к инциденту.

5. **Держите live-ISO рядом.** `poler-cachyos-x86_64-<ver>.iso` всегда
   гибрид BIOS+UEFI и содержит rescue-режим — это ваш ключ от двери.

## Что сделано в v1.2.0

| Защита | Механизм |
|--------|----------|
| Главная оболочка консолей | poler-engine v0.61.0 Terminal Gateway — официальный релизный бинарник, sha256-pinned (`abd6e98b…`) |
| Аварийная оболочка | poler-sh остаётся в образе; login-shell root в `/etc/passwd` — `poler-sh` |
| Rescue-режим | GRUB-запись «POLER Sovereign Rescue»: `poler.rescue=1` — движок обходится, консоль = poler-sh |
| Авторский фолбэк PID 1 | poler-init: если poler-engine не запускается/падает — сессия перезапускается на poler-sh |
| Питание без Bash | `reboot`/`poweroff`/`halt` = poler-powerctl (marker-IPC к PID 1) — работает из песочницы движка |
| Записываемые области | tmpfs на `/run`, `/tmp`, `/root/.cache`, `/var/tmp` — движку не нужна запись в read-only squashfs |
| Канал движка на любую систему | `poler-update --install engine` — тот же официальный бинарник, тот же sha256-пин |
| Ничего не удаляется вслепую | poler-update только добавляет/заменяет бинарники атомарно; политика «не сносить легаси без фолбэка» — в этом документе |

## Чек-лист перед изменением загрузочной цепочки

```
[ ] новый shell запущен и протестирован в ЭТОМ сеансе (пайпы, редиректы, vi)
[ ] /etc/passwd содержит фолбэк-shell, отличный от нового
[ ] rescue-путь известен и записан (poler.rescue=1 / live-USB / chroot)
[ ] контролируемая перезагрузка запланирована на СЕЙЧАС, не «потом»
[ ] свежий live-ISO под рукой
```
